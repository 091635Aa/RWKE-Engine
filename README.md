# RWKE-Engine

> **一句话定位**：把 Transformer 时代成熟起来的「情感回响注入」原样搬到 RWKV-7 递归底座上，用 O(1) 的 State 承载人设、日记与长对话记忆的本地推理引擎——本仓库是它的**轻量、已脱敏、可公开的快照**。

---

## 0. 这个仓库是什么，不是什么

**是什么**

- 一个**能跑起来的 RWKV-7 推理引擎**：自实现逐层前向、注入/捕获/采样链、State 挂载与导出、多轮对话（延续对话 / 软重锚 / eos 保护 / 复读压制）。
- 一个 **OpenAI 兼容的本地服务**：`服务器.py` + `启动服务器.bat`，默认端口 8102，可作为任意 OpenAI Compatible 客户端（例如 AIRI）的后端。
- 一份**完整的方法与实测档案**：`docs/` 下有测试报告、微调报告、注入策略对比、100 轮连续对话演示，以及从 Transformer 迁移到 RWKV-7 的完整迁移方案（md + pdf）。
- 一份**面向新读者的科普**：`RWKV_小白入门图文/`（7 张 SVG 插图 + 图文长文），解释 RWKV 与 Transformer 的架构/显存差异。

**不是什么**

- **不是全量工程**：模型权重、日记 State、LoRA 适配器、角色包 zip、训练语料、原始实验结果都不在本仓库（见文末「未收录清单」）。
- **不是「开箱即用」**：代码是快照，模型路径、数据路径、CUDA 工具链需要按本机调整；数据生产链没有公开。
- **不是已完成的产品**：它是一套可复现的实验底座，边界与未达标项都写在「诚实边界」一节，请先读那一节再引用任何数字。

## 2. 核心实测读数（可直接引用的数字）

以下读数的来源都在 `docs/` 内；环境为单机 **Python 3.10.11 / torch 2.6.0+cu124 / RTX 3080 Laptop 16GB**，统一采样协议为 T=1.0、top_p=0.9、top_k=50、repetition_penalty=1.05、seed=42、max_new_tokens=256。

| 指标 | 读数 | 出处 |
|---|---|---|
| **State 显存恒定（O(1)）** | 0.4B：**6.09 MB**；1.5B：**12.19 MB**，0 / 512 / 2048 深度三档完全一致 | `docs/RWKE测试报告.md` §3 |
| **100 轮连续对话 State** | 全程恒定 **12.2 MB**，纹丝不动 | `docs/连续对话演示报告.md` |
| 同场景 Transformer KV 对照 | Qwen2.5-1.5B @2048 深度 KV 缓存 **56.44 MB**，随深度线性增长（0.4B 级为 24.19 MB） | `docs/RWKE测试报告.md` §3 |
| 深度延迟（0/512/2048） | 0.4B：38.29 / 31.04 / 33.85 ms；1.5B：32.83 / 26.55 / 27.82 ms（基本平坦） | 同上 |
| **注入显著性 ΔH（语义熵差）** | 0.4B λ=0.1：**ΔH = +0.125**；1.5B λ=0.1：**ΔH = +0.267** | `docs/RWKE迁移方案.md` §8 |
| **最终 λ** | **λ = 0.1**（0.4B 插值初值 λ=0.416 过强导致重复率 0.77 → λ=0.05 时 ΔH=0.046 不显著 → 定 λ=0.1；1.5B 的「注入即停」根因是偏置在 eos 维度的正分量，加入 eos 保护后 λ=0.1 认证通过） | `RWKE迁移方案.md` §8 / `系统配置.json` |
| 认证矩阵 | 4 个模型全部 PASS（RWKV7-World-0.4B / 1.5B、Qwen2.5-1.5B / 0.5B），判定四条件：无 NaN、\|ΔH\|>0.05、4gram 重复率不高于裸+0.15、生成可持续 | `docs/RWKE测试报告.md` |
| 情感增幅（可信口径） | 1.5B 挂日记 State + 注入 vs 裸：情感词密度 **0.207 vs 0.062 / 千字 = +234%**（超过 +70% 目标线） | `docs/注入策略对比报告.md` §6 |
| 条纹率（长会话重复） | 1.5B：裸 0.0166，现行注入 0.4721，缓和注入 0.0471 | 同上 §5 |

> 引用时请保留「单卡 3080 / 离线 / 100 轮」这些限定条件。不同轮次的绝对毫秒数会有波动，趋势（平坦 vs 线性）才是结论。

## 3. 怎么跑

### 3.1 环境

```powershell
# 建议 Python 3.10+；torch 按本机 CUDA 选择构建
pip install -r requirements.txt
# 可选：情感词密度（缺失时脚本自动回退本地词表）
pip install cnsenti
```

运行时要点（迁移方案 §4）：

- `RWKV_V7_ON=1` 必须在 `import rwkv.model` 之前生效（引擎已在模块顶部处理并带 V7 分派守卫）；
- `RWKV_CUDA_ON=1` 需要 nvcc + MSVC，编译失败会自动降级纯 PyTorch；纯 PyTorch 模式逐位可复现，CUDA 算子模式递推快但数值有 ~4e-2 偏离；
- `RWKV(路径, strategy)` 的路径**不带 `.pth` 后缀**，strategy 形如 `cuda fp16` / `cpu fp32`；
- 模型统一放在仓库根的 `models/` 下（路径相对 `系统配置.json` 书写），本仓库不附带权重。

### 3.2 拉模型 → 起服务

```powershell
python 下载模型.py --check          # 只检查矩阵缺哪些
python 下载模型.py                  # 全矩阵约 6.6 GB；也可 --仅模型 RWKV7-World-0.4B
python 服务器.py --模型 RWKV7-G1-1.5B --角色 EmoCompanion --端口 8102 --快速采样
# 或直接双击 启动服务器.bat
```

OpenAI Compatible 客户端配置：Base URL `http://127.0.0.1:8102/v1`，API Key 任意非空，Model `rwkv7-g1-1.5b`。

### 3.3 本地对话与角色 State

```powershell
python 对话系统.py                                   # 最快：0.4B + 测试角色
python 对话系统.py --角色 EmoCompanion --模型 RWKV7-G1-1.5B
python 日记状态.py --模型 RWKV7-World-0.4B           # 生成日记 State .pth
python 日记状态.py --自检解析                        # 无模型时做解析自检
python 角色包.py 校验 EmoCompanion                   # 角色包完整性检查
```

**配套仓库**：环境自检（`测试_环境自检.py`）、冒烟（`测试_冒烟.py`）、多模型认证（`测试_对比.py`）、100 轮连聊（`测试_连续对话.py`）在 **RWKE-Training**；训练与评估脚本也在那里。本仓库只放「引擎 + 服务 + 状态通道 + 文档」。

## 4. 与 `01_Transformer架构` 的关系

`01_Transformer架构` 是上一代战场：P1 语义回响、P1.5 兼容层、P2.5 情感潮汐解码、P3 锚点回响、P4 KV 情感共振、P5 超融合、P6 情感导演，全部建立在 **Transformer 的 KV Cache / 注意力干预**之上，已优化到该路线的极限并归档。

RWKE 做的事是**最小改动、最大复用**：上层逻辑（末 N 层 hidden 捕获 → 不确定性过滤 → 回响池衰减/质心 → Kaiming/随机投影 → `logits += 质心 @ 投影 × λ` → 自定义采样循环）与 01 的方案**逐行等价**，只把推理底座换成 RWKV-7。对应的映射关系：

| Transformer（01） | RWKV-7（本仓） |
|---|---|
| KV Cache，O(n) 随序列增长 | 扁平 State List，O(1) 恒定 |
| 日记/人设注入挤占上下文窗口 | State 预填充，不占窗口 |
| 每步注意力开销 ∝ 历史长度 | 每步开销恒定 |
| forward hook 捕获 hidden_states | 自实现单步前向，内联逐层残差输出（jit 后 hook 不可用） |

详细映射（`past_key_values` ↔ `att_x_prev/att_kv/ffn_x_prev`、`generate` ↔ 自实现采样循环、eos 双重停止等）见 `RWKE迁移方案.md` §3。

一句话：**01 证明「情感注入」这件事有效，02 换掉它昂贵的地基。** RWKE 的增益主要来自 State 的 O(1) 记忆与零窗口占用，而不是更强的注入。

## 5. 与 `03_AHI`（自我意识体项目）的关系

- `03_AHI` 的主线是「自我意识体」，不是推理引擎/模型架构的复刻；它的铁律里明确**禁 Transformer 复刻、禁外挂模型当器官、要求确定性可复现**。
- RWKE 用的是递归 RWKV-7，方向与 AHI 的「内生、非 Transformer」路线一致；它提供的是 **O(1) 长记忆 + State 人设注入 + 状态持久化** 的可复现实验底座，与 AHI 关心的「同一性 / 连续记忆 / 长期一致」高度相关。
- 但需要说清楚：**本仓库是 `02` 的独立工程，AHI 主线（视觉、文本态等）没有直接 import 本仓代码**；两者是并行的储备关系，不是依赖关系。以 `03_AHI` 目录内文档为准，不要从本 README 推断 AHI 的当前状态。

## 7. 诚实边界（请勿跳过）

1. **World 基座的复读边界**：RWKV-World 系列是未经对话指令对齐的基座。连续 20~30 轮后三种模式都会出现句式复读（0.4B 约 7 轮起）。框架层的四层缓解（会话级重复惩罚、连续重复压制、开场 eos 禁步、软重锚）把「单字爆走 / 空回复」清零，但**句式复读仍在**——那是基座边界，不是框架缺陷；根治要换对话对齐模型（RWKV7-G1）。换到 G1 后裸模型提升明显（100 轮五维 47.2 → 64.9），但**注入在 G1 上仍会在约 11 轮后形成模板循环**，因此推荐配置是「G1 裸模型 + State 记忆框架 + 注入强度收敛到极低或按需触发」。
2. **记忆突击测试未命中**：100 轮间隔 25/55/95 轮提问埋点，三模式命中数分别为 1/3、0/3、1/3。长会话复读吞掉了记忆表达；框架提供了软重锚与日记 State 回锚机制，换对话对齐模型后该能力才有机会释放。**「100 轮记忆测试 3/3」是科研验收目标，不是本快照的现状。**
3. **情感增幅目标未达成**：0.4B 上现行注入为 -89.4%，缓和注入 -16.6%；1.5B 上 S2 的 +381% **不可采信**（20~30 轮后退化为英文词循环，条纹率 0.47，高密度来自退化文本的统计噪声）。可信口径是长会话可读内容的 +234%。**300%/400% 目标在 World + 100 轮场景没有以可信方式达成。**
4. **λ 不能硬拉**：λ≥0.2 在 0.4B 上直接触发 attractor（三档爬坡结果一致）；「有界自动标定」最多 3 档、达标即停，没有无限循环模式。
5. **HybridRWKV-T 未落地**：双路径路由（Token 级动态路由 + 跨路径投影读取器 + 路由后重对齐层）只存在于 `03_AHI` 科研报告与路线图中，**本仓库没有任何实现**；它的主要风险是两路训练动力学不同、早期路由随机导致隐空间分裂。
6. **代码是快照**：路径、模型标识、CUDA 工具链版本都按作者本机写死，换机器需要改 `系统配置.json` 与 `启动服务器.bat`；**数据生产链（打标 → 日记语料 → 训练集）没有公开**，`日记状态.py` 找不到语料时会走解析自检分支。
7. **复现口径**：报告里的延迟/显存是单卡 RTX 3080 Laptop 的离线读数；tokens/s 约 25~32（0.4B）/ ~32（1.5B，CUDA 算子路径）。换硬件数字会变，但「State 与深度无关」的结论可复现。
